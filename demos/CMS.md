# The client editor (Decap CMS)

Every demo site ships with an editor at `/admin/` so the client can change
their own text, prices and photos after handover. This is how the "update it
yourself" promise on the main site is kept, with no database and no monthly fee.

## How it works

```
client edits at        Decap commits          Netlify builds          site is live
plumbing.launch250     content.json (+photos)  python3 _build.py       ~60 seconds
.co.uk/admin     --->  to the GitHub repo  --> plumbing           -->  later
```

- **`demos/<slug>/content.json`** holds everything the client may change:
  names, phone, email, hours, logo, three photos, headline, intro, trust
  points, services and prices, about copy, three stats, areas, reviews, FAQ.
- **`demos/_sites.py`** holds everything they may not: colours, fonts, hero
  style, radii, overlay tints. Design stays ours.
- **`_build.py`** merges the JSON over the design entry and renders the site.
  Building with or without the JSON gives identical output, so nothing changes
  at handover; the JSON just becomes the thing that gets edited.
- **`demos/<slug>/admin/`** (`index.html`, `config.yml`) and
  **`demos/<slug>/netlify.toml`** are generated by `_build.py` from `_cms.py`
  and `_deploy.py`. Never edit them by hand; edit the generator.

Photos: the editor converts uploads to WebP no wider than 2000px in the
browser before saving (`media_processing` in config.yml), and `_build.py`
does the same again at build time for anything that slips through. Uploads
live in `demos/<slug>/img/uploads/`.

## Setting up a new site (once per client, about 15 minutes)

1. **Netlify site.** Netlify → Add new site → Import from Git → this repo.
   Set *Package directory* to `demos/<slug>` and leave *Base directory* blank.
   The `netlify.toml` in that folder supplies the build command, publish
   folder and Python version. Deploy once.
2. **Domain.** Netlify → Domain management → add `<slug>.launch250.co.uk`,
   then add the CNAME it gives you at the DNS provider for launch250.co.uk.
   HTTPS is automatic.
3. **Login service.** Netlify has deprecated Git Gateway for new sites, so the
   editor uses [DecapBridge](https://decapbridge.com) (free, built for this).
   Register the site there with this repo and the `main` branch, copy the
   *site id* it gives you into `BRIDGE['<slug>']` in `demos/_deploy.py`, run
   `python3 _build.py <slug>`, commit and push. Until the id is set, `/admin`
   shows a "not switched on yet" note instead of a login that cannot work.
4. **Invite the client.** In DecapBridge add the client as a collaborator
   with their email. They get an invite, set a password, and log in at
   `https://<slug>.launch250.co.uk/admin/`.
5. **Send the video.** One recording covers every site because the editor is
   identical. Suggested three minutes: log in → change a price → change a
   photo → Publish → refresh the site a minute later.

Repeat step 1 per site: one Netlify site per subdomain, all from this one repo.
Netlify only rebuilds a site when files under its own folder (or the shared
generator) change, so a plumbing edit does not rebuild the barbers.

## Testing the editor locally (developers)

```
cd launch250
npx decap-server            # local proxy on :8081, needs internet for the first run
python3 -m http.server 8777 # in a second terminal
open http://localhost:8777/demos/plumbing/admin/
```

`local_backend: true` in config.yml makes the editor talk to the proxy and
edit your working copy with no login. Rebuild with `python3 demos/_build.py
plumbing` to see the result. Whatever the client would do, you can do here first.

Quick checks without a browser:

```
python3 demos/_build.py           # output must not change when content.json is untouched
python3 -c "import yaml; yaml.safe_load(open('demos/plumbing/admin/config.yml'))"
```

## Changing what clients can edit

Add the key to `CONTENT_KEYS` and the conversions in `_content.py`, add the
matching field in `fields_yaml()` in `_cms.py`, re-export with
`python3 _content.py export`, rebuild. The validation in `_cms.py`'s field
list and `content.json` must stay in step or Decap will show the field empty.

## What the client cannot break

- Colours, fonts and layout: not in the editor.
- The site while editing: nothing changes until they press Publish, and every
  publish is a Git commit, so any change can be reverted from the repo history.
- Photo sizes: shrunk automatically twice.
- Search snippets: the tab title and Google description are fields with hints
  on length; they are the only SEO surface exposed.
